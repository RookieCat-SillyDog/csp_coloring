# 实验前端布局与视觉优化规划

**创建时间**: 2026-06-03  
**状态**: 规划阶段  
**负责范围**: 认知实验界面的视觉呈现、空间利用、学术审美优化

---

## 一、优化目标

### 1.1 核心问题
- **空间利用率低**: 当前左右竖向分栏浪费横向空间，被试需频繁上下滚动
- **信息割裂**: 图、报告表、响应区域距离远，视线跳跃负担重
- **配色不学术**: 红绿蓝饱和度过高，不符合认知实验中性审美
- **节点层级不清**: 目标士兵、当前报告士兵、已报告士兵的视觉区分度不足

### 1.2 优化目标
1. **减少滚动**: 将核心信息控制在一屏内，减少被试滚动操作
2. **横向布局**: 充分利用 16:9/16:10 显示器的横向空间
3. **学术配色**: 红绿蓝改为低饱和度学术风格
4. **视觉层级**: 强化目标节点、当前报告节点、已报告节点的视觉区分

## 二、设计规范

### 2.1 布局结构

#### 新布局方案
```
┌──────────────────────────────────────────────────────────────┐
│ [进度指示]  判断目标士兵的阵营    目标士兵: E    [当前题目]   │
├────────────────────────┬─────────────────────────────────────┤
│                        │  ┌─ 新收到的报告 ─────────────────┐ │
│                        │  │ 士兵 D: [报告表横向]           │ │
│    图 (左侧区域)        │  └─────────────────────────────────┘ │
│                        │  ┌─ 已收到的报告 ─────────────────┐ │
│   (宽高比约 4:3)        │  │ 士兵 A, B: [横向卡片流]        │ │
│                        │  └─────────────────────────────────┘ │
│                        │  待送达: [士兵 F] [士兵 H]          │
│                        │  ─────────────────────────────────── │
│                        │  选择颜色: [红色] [绿色] [蓝色]      │
│                        │  信心程度: [=======○======] 75      │
│                        │            [提交回答]                │
└────────────────────────┴─────────────────────────────────────┘
```

#### 关键尺寸
- **容器最大宽度**: 1480px（当前 1400px 偏窄）
- **图区域**: 占比 55%（当前约 60%，略减少给右侧更多空间）
- **右侧面板**: 占比 45%
- **报告表**: 横向排列，每张宽度 140-160px
- **整体高度目标**: 控制在 85vh 内，避免滚动

### 2.2 配色规范

#### 学术配色（低饱和度）
```css
/* 主色：低饱和度红绿蓝 */
--color-red: #d84a3f;          /* 降饱和的红，避免刺眼 */
--color-green: #44a35c;        /* 稍灰化的绿 */
--color-blue: #4b7fc4;         /* 学术蓝，接近期刊配色 */

/* 悬停态：略深但不过分 */
--color-red-hover: #c23d33;
--color-green-hover: #389050;
--color-blue-hover: #3b6ba8;

/* 目标士兵：暖灰+金棕系（区别于蓝色报告标记） */
--color-target: #d4874a;       /* 暖橙棕 */
--color-target-soft: #fef7ed;  /* 极淡暖底 */
--color-target-ring: #e6a367;  /* 柔和金色 */

/* 报告状态标记 */
--color-report-current: #5b68c4;        /* 深蓝紫，强于背景 */
--color-report-current-soft: #e8eaf6;   /* 淡紫底 */
--color-report-past: #94a3b8;           /* 更灰，降低视觉权重 */
--color-report-hidden: #cbd5e1;         /* 浅灰 */
```

#### 配色使用规则
1. **红绿蓝仅用于士兵填色和选项按钮**，不用于装饰元素
2. **目标士兵用暖色系**，与报告标记的冷色系区分
3. **灰度系统**用于文本、边框、背景
4. **避免高对比度组合**（如纯白配纯黑），使用灰阶过渡

### 2.3 图节点视觉规范

#### 节点状态层级（从高到低）
1. **目标士兵（最高优先级）**
   - 描边: 7px 暖橙棕 `#d4874a`
   - 背景: 极淡暖底 `#fef7ed`
   - 外圈: 虚线金色环 + 轻微投影
   
2. **当前新报告士兵（次高）**
   - 描边: 5.5px 深蓝紫 `#5b68c4`
   - 背景: 淡紫底 `#e8eaf6`
   - 外圈: 实线蓝紫环 + 呼吸动画（可选）

3. **已报告士兵（低调）**
   - 描边: 3px 中灰 `#94a3b8`
   - 背景: 极淡灰 `#f8fafc`
   - 外圈: 短虚线灰环
   - 整体不透明度: 0.85

4. **待报告士兵（占位）**
   - 描边: 2.5px 浅灰 `#cbd5e1`
   - 外圈: 点状虚线
   - 不透明度: 0.65

5. **无报告普通士兵**
   - 描边: 3px 边框灰 `#cbd5e1`
   - 背景: 白色

#### 边的视觉规范
```css
.graph-edge {
  stroke: #cbd5e1;           /* 当前偏深，改为更浅的灰 */
  stroke-width: 4;           /* 当前 6px 过粗，减为 4px */
  stroke-linecap: round;
  opacity: 0.5;              /* 新增：降低边的视觉权重 */
}
```

### 2.4 报告表横向卡片规范

#### 单张报告表尺寸
- **宽度**: 150px（紧凑）
- **内边距**: 10px
- **行间距**: 减少到 4px
- **字号**: 标题 14px，颜色标签 13px，次数文本 11px

#### 横向排列规则
- **当前报告**: 单独占一行，带深色边框和淡色背景
- **已收到报告**: 横向 `display: flex; flex-wrap: wrap; gap: 10px;`
- **待送达**: 只显示士兵 ID，不显示完整表格

#### 视觉简化
- **去掉右侧次数列**: 只保留离散报告格
- **报告格尺寸**: 11px → 13px（更易识别）
- **行间距**: 6px → 4px（更紧凑）

## 八、Codex 评审意见与修订建议

**评审时间**: 2026-06-03  
**评审结论**: 方案方向正确，但不建议原样执行。应优先解决正式 trial 操作效率和反应时稳定性问题，再处理配色和微交互。

### 8.1 可以采纳的方向

1. **横向工作台布局是正确方向**

当前左右两个高竖卡片导致被试需要上下滚动。正式 trial 应改成更紧凑的实验工作台布局，让图、报告表和作答区尽量同时可见。

2. **正式 trial 报告区分层合理**

“新收到的报告 / 已收到的报告 / 待送达”与正式 trial 的 4 步序贯揭示逻辑一致，应保留。

3. **节点状态需要更清楚**

目标士兵、当前新报告士兵、已报告士兵、待送达士兵应有稳定视觉区分。目标士兵与报告士兵不能使用同一种高亮逻辑。

4. **红绿蓝降低饱和度可以做**

当前红绿蓝偏网页按钮风格。低饱和度、更克制的配色有助于让界面更像认知实验，而不是游戏或网页产品。

### 8.2 不建议采纳的点

1. **不建议去掉 `x次` 次数列**

Phase 3 中提出“去掉右侧次数列，只保留离散报告格”。不建议这样做。

原因：

- `x次` 是报告表的辅助读数，可以减少被试逐格数数的负担。
- 正式任务中报告表是观察报告计数，不是装饰性图形；数值读数有助于清晰理解。
- 之前已经决定报告表用“5 个离散报告格 + 次数文本”的形式，不应在没有新证据的情况下删除次数文本。

修订建议：

```text
保留 x次，但降低视觉权重：
- 字号 11-12px
- 固定窄列
- 使用 muted text color
- 不做胶囊、不加醒目背景
```

2. **不应追求整个页面 85vh 内完全无滚动**

正式 trial 第 4 步会同时有 4 张报告表。如果硬压进 85vh，容易导致报告表过小、文本拥挤或作答区被挤压。

更合理的目标：

```text
body 不滚动
图区域固定可见
作答区固定可见
报告表区域允许内部滚动
```

也就是说，可以允许右侧报告列表内部滚动，但不能让被试为了选择颜色、调整信心或提交而滚动整个页面。

3. **报告表 140-160px 可能偏窄**

如果报告表保留颜色标签、5 个报告格和 `x次`，150px 很容易挤压。正式实验中可读性优先于极限紧凑。

修订建议：

```text
当前新报告：全宽或至少 220px
已收到报告：紧凑卡片，建议 180-200px
待送达：只显示士兵 ID 标签
```

4. **不建议默认使用呼吸动画**

当前报告士兵需要突出，但不建议用持续动画。动画可能吸引注意、影响阅读节奏，也可能影响 RT。

修订建议：

```text
默认使用静态强调：
- 更深描边
- 实线外圈
- 浅底色

不使用持续呼吸动画。
```

5. **正式 trial 标题区应进一步压缩**

“判断目标士兵的阵营”不需要在正式 trial 每一步都以大标题呈现。被试已经知道任务，正式阶段更需要节省纵向空间。

修订建议：

```text
顶部压缩为一行：
正式实验 · 当前题目 · 第 2 / 4 步 · 目标士兵 E
```

任务说明可以保留为较小字号的一行，不应占据大段高度。

### 8.3 推荐执行顺序

建议调整原计划优先级：

```text
Phase 1: 布局重构
Phase 2: 正式报告表紧凑化，但保留 x次
Phase 3: 作答区固定可见
Phase 4: 配色与节点层级优化
Phase 5: 微交互打磨
```

理由：

当前最影响实验体验和数据质量的是滚动，而不是配色。频繁滚动会改变反应时、增加操作负担，并让正式 trial 的 step 更新过程变得不稳定。因此应先处理一屏可操作问题。

### 8.4 建议的最终布局原则

正式 trial 应采用以下原则：

```text
整页使用 100vh
页面主体不滚动
左侧图始终完整可见
右侧作答区始终可见
报告表区域可内部滚动
当前新报告优先显示
历史报告紧凑显示
待送达只显示士兵 ID，不显示报告内容
```

### 8.5 实现审查标准

实现后至少检查：

1. 正式 trial 第 1 步不需要滚动即可看到图、当前报告、颜色选择、信心和提交按钮。
2. 正式 trial 第 4 步作答区仍然固定可见。
3. 如果报告表过多，只允许报告表列表内部滚动。
4. `x次` 次数文本仍然存在，并且不重叠。
5. 当前新报告士兵与已报告士兵视觉可区分。
6. 无持续动画干扰。
7. `npm run validate:stimuli` 和 `npm run build` 通过。

### 8.6 最终建议

Claude 方案可作为布局优化基础，但需要按上述原则修订。当前不建议先实施配色 Phase 1；应先实施布局和作答区固定可见。正式实验界面的主要目标不是视觉新鲜感，而是让被试在每一步稳定、快速、低负担地完成判断。
